StarDreamerChaosmos · 目标架构图

设计是微服务,部署是单体 · 路由 → 业务函数(校验+认证) → 全局拨号器 → 微服务 → 响应

分层与启动顺序

  • • 内核 → bus → 支柱(flag/config) → 业务组件
  • • bus 是内核之上最底层,状态唯一出口
  • • flag / config 是支柱,必须先上
  • • 宿主逐个 Enable = 手动控制启动顺序

组件三类拆分

  • • 脚手架:auth / register(所有业务依赖)
  • • 共享:user / comment / interaction / notify…
  • • 业务域:博客 / 视频 / 网盘各自独有
  • • 跨域公共上抽,绝不按线复制

业务执行标准

  • • 路由命中 → 业务函数(参数校验 + 认证)
  • • 业务函数不直连服务,一律走全局拨号器
  • • 拨号器按服务键调用微服务,拿到结果
  • • 组装统一信封返回响应

单体 → 多体的开关

  • • 全局拨号器是业务与微服务的唯一出口
  • • 单体:地址指向本进程 ≈ 直接调用
  • • 拆分:地址指向远程,自动跨网络 + 负载均衡
  • • 业务只认服务键,换部署不改业务
